1. 项目结构：哪些带、哪些不带

当前项目根目录：E:\开发练习项目\录屏软件\。真实结构如下，"是否同步"一列请严格执行。

路径内容同步原因
ScreenRecorder\*.cs / *.xaml产品全部源码（17 个文件）必须产品本体
ScreenRecorder\ScreenRecorder.csproj工程定义、版本、NAudio 引用必须决定能否编译
ScreenRecorder\tools\ffmpeg.exe编码组件，125.6 MB必须没有它无法编码，不能单独移动
spike\（16 个工程）S1–S5 验证、端到端、基准、热键测试建议验收工具都在这里，MvpE2E 是回归测试入口
build-package.ps1绿色版打包脚本必须改完代码靠它重新出包
.gitignore同步忽略规则（本轮新增）必须防止把个人数据和编译垃圾带过去
README.html、5 份阶段 HTML 文档使用说明、规划与验证报告建议不改代码也无害，约 150 KB
publish\已打好的绿色包与解压目录不由脚本现场生成，带过去纯属重复占空间
**\bin\、**\obj\本机编译产物不含绝对路径缓存，跨机易出增量编译怪错
settings.json、logs\、Videos\个人配置、日志、试录视频（当前 195 MB）严禁含本机路径与个人录像；过去会让新电脑按错误路径保存
spike\ffmpeg6\、spike\ffmpeg_new\、*.7z下载缓存与旧版备份（约 400 MB）不纯临时文件，产品只用 ScreenRecorder\tools\ffmpeg.exe
体积参考：按上面规则同步，源码包约 135 MB（其中 FFmpeg 占 126 MB）；如果把临时文件一起拷，会膨胀到 500 MB 以上。已在本轮创建 .gitignore 固化这套规则。

2. 依赖与运行环境准备

2.1 必装（只有一项）

项目要求验证方法
操作系统Windows 10 / 11，64 位设置 → 系统 → 关于
.NET SDK8.0.428（当前开发机版本，建议对齐）打开 PowerShell，运行 dotnet --version，应输出 8.0.428
踩过的坑：不要用 Git Bash 跑 dotnet——它的 PATH 里没有 dotnet，会报 dotnet: command not found。请用 PowerShell，或一律写全路径 C:\Program Files\dotnet\dotnet.exe。本指南所有命令都按 PowerShell 书写。

2.2 联网自动获取（不用手动下载）

包版本谁用
NAudio2.2.1产品工程、AudioSpike、MvpE2E、TonePlayer
Microsoft.Windows.CsWinRT2.0.4仅 WPFCheck、S2GC 两个 Graphics Capture 验证工程

第一次编译会自动从 NuGet 还原。若公司网络需要代理，先在 PowerShell 配置 HTTP_PROXY / HTTPS_PROXY；否则会卡在还原阶段。还原命令（可选，提前跑）：

& "C:\Program Files\dotnet\dotnet.exe" restore "D:\ScreenRecorder\ScreenRecorder\ScreenRecorder.csproj" --nologo

2.3 随项目携带（不用下载）

ScreenRecorder\tools\ffmpeg.exe，FFmpeg 6.0 full build，125.6 MB。版本很关键：这是基于 NVENC SDK 12.0 构建、能匹配当前显卡驱动 527.27 的版本。不要"顺手升级"到新版 FFmpeg——新版要求驱动 ≥610，会直接报 NVENC API 版本错误。校验值见附录。

2.4 可选，产品不需要

  • Windows SDK 10.0.26100：只有重新验证 Graphics Capture（spike\WPFCheck）时才需要。产品和其余 spike 工程都不需要；而 GC 已冻结，绝大多数情况用不上。

2.5 明确不需要的

无需管理员权限、无需账号密码、无需许可证、无需数据库、无需云服务、无需开放端口。程序不写注册表、不联网上传任何数据。
首次双击可能出现 Windows SmartScreen 提示（因为程序未做数字签名）：点「更多信息」→「仍要运行」即可。若单位策略禁止，需要 IT 部门放行。

3. 项目文件同步（三种方案）

方案 A：直接拷贝源码包（推荐，最简单）

  1. 在原电脑打包源码——打开 PowerShell，逐行执行（目标路径可自选）： 
    $src = "E:\开发练习项目\录屏软件"
$dst = "D:\源码包\录屏软件"
robocopy $src $dst /E /XD bin obj .vs publish Videos logs ffmpeg6 ffmpeg_new /XF settings.json *.mp4 *.7z *.wav *.raw *.gray
Compress-Archive -Path "$dst\*" -DestinationPath "D:\录屏软件_源码包.zip" -CompressionLevel Optimal -Force
    robocopy 返回码 1 表示"复制成功"，属正常现象。
  2. 拷贝 D:\录屏软件_源码包.zip 到 U 盘或网盘，带到新电脑。
  3. 解压到可写目录，例如 D:\ScreenRecorder\。
    不要解压到 C:\Program Files：那里默认不可写，配置 settings.json 和日志会失效或退到 AppData，破坏"删除目录即卸载"。
  4. 删除可能残留的编译目录（即使打包时排除了，也再确认一次）： 
    Get-ChildItem "D:\ScreenRecorder" -Recurse -Include bin,obj -Directory | Remove-Item -Recurse -Force

方案 B：用 Git 同步（推荐长期维护）

仓库已建立（公开）：https://github.com/JOIN007103/screen-recorder。已推送 84 个源码与文档文件，提交历史使用 noreply 邮箱，不含个人邮箱、令牌或试录视频。

  1. 新电脑安装 Git 与 .NET SDK 8.0.428，任选目录打开 PowerShell，克隆： 
    git clone https://github.com/JOIN007103/screen-recorder.git D:\ScreenRecorder
  2. 补回 FFmpeg（必做）：GitHub 单文件上限 100MB，ffmpeg.exe（125.6MB）无法入库，故未随源码上传。在克隆目录运行随包的获取脚本，它会自动下载 FFmpeg 6.0、校验 SHA256 并放回 ScreenRecorder\tools\： 
    cd D:\ScreenRecorder
powershell -ExecutionPolicy Bypass -File .\fetch-ffmpeg.ps1
    脚本自带 7zr 解压器下载，无需预装工具；国内网络会自动走镜像源。看到「SHA256 校验通过」即成功。
  3. 核对文件：ScreenRecorder\tools\ffmpeg.exe 应已存在（125.6MB）。哈希校验值见附录。
  4. 后续修改同步：git add -A && git commit -m "改动说明" && git push。HTTPS 推送需要个人访问令牌（PAT），建议设置有效期并只勾 repo 权限，用完及时删除。

注意：本机若配置了指向 127.0.0.1 的代理且该代理不通，Git 会报 CONNECT tunnel failed 502。此时用 git -c http.proxy= -c https.proxy= push 绕过代理即可。

方案 C：只分发绿色版

把 ScreenRecorder_v1.0.0_green.zip 和 .sha256.txt 一起发出。对方校验哈希后解压即用，不需要本指南。

4. 新电脑本地运行验证（三层，逐层做）

第 1 层：编译通过

cd D:\ScreenRecorder
& "C:\Program Files\dotnet\dotnet.exe" build "ScreenRecorder\ScreenRecorder.csproj" -c Release --nologo

预期：0 个警告，0 个错误。

第 2 层：真实引擎端到端

& "C:\Program Files\dotnet\dotnet.exe" build "spike\MvpE2E\MvpE2E.csproj" -c Debug --nologo
& "D:\ScreenRecorder\spike\MvpE2E\bin\Debug\net8.0-windows\MvpE2E.exe"

预期输出：总帧数: 180、耗时约 6.0 秒。再用 ffprobe 复核（ffprobe 在 spike\ffmpeg6\ffmpeg-6.0-full_build\bin\，若按方案 A 排除了该目录，可临时拷过来）：

ffprobe -v error -show_entries stream=codec_name,codec_type,nb_frames -show_entries format=duration -of default=nw=1 "输出文件.mp4"

预期：h264 / 180 帧 / duration=6.000000 + aac 单音轨。

第 3 层：界面冒烟（真人五分钟）

  1. 双击 ScreenRecorder\bin\Release\net8.0-windows\ScreenRecorder.exe，界面显示「编码组件：已就绪 ✓」。
  2. 点标题下方蓝色「v1.0.0 · 关于」，确认版本弹窗正常。
  3. 按 F9 → 等 3 秒倒计时 → 按 F10。
  4. 检查三件事：Videos\ 出现 MP4；logs\run_日期.log 有启动与录制记录；成片里没有悬浮控制条。
  5. 正常关闭窗口，确认 settings.json 写入。

常见失败对照

5. 修改后的同步与备份流程

5.1 改之前：先备份

$date = Get-Date -Format "yyyyMMdd_HHmm"
Copy-Item "D:\ScreenRecorder" "D:\ScreenRecorder_backup_$date" -Recurse -Force

命名建议 ScreenRecorder_backup_20261118_1035。备份保留最近 3 份即可，用完及时清理，避免磁盘膨胀。

5.2 改的时候：三条铁律

  1. 产品代码只改 ScreenRecorder\ 下的文件；spike\ 是验证工具，不要在里面写产品逻辑。
  2. 新增 NuGet 包或 WPF 依赖时，必须同步修改 spike\MvpE2E\MvpE2E.csproj（以及链接了产品源码的 PerfProbe.csproj）。这两个工程用 <Compile Include="../../ScreenRecorder/Services/*.cs"> 直接吃产品源码——本项目中 NAudio 和 UseWPF 已经各踩过一次漏同步的坑。
  3. 若更换 FFmpeg 版本，必须重新实测 NVENC，并更新附录的 SHA256 基线。

5.3 改之后：四步验收

  1. Release 构建 0 警告 0 错误。
  2. 跑 MvpE2E，确认 180 帧 / 6.000s / 音轨存在。
  3. 界面冒烟，检查 logs\ 没有新增 ERROR 行。
  4. 重新出包（脚本会自动先构建）： 
    powershell -ExecutionPolicy Bypass -File "D:\ScreenRecorder\build-package.ps1" -Build

5.4 同步回另一台电脑

  • Git：git add . && git commit -m "改动说明" && git push，另一台执行 git pull。
  • 拷贝：只覆盖源码文件，不要覆盖对方的 settings.json 和 Videos\；覆盖前按 5.1 备份。
  • 两边都核对一次 ScreenRecorder\tools\ffmpeg.exe 的哈希，防止版本漂移。

6. 冲突与注意事项（13 项，按严重度排序）

问题后果规避
1. settings.json 两台互相覆盖新电脑按旧电脑的路径保存，录到找不到的位置永不同步此文件；换机后删除它，让程序用默认值重建
2. 跨机拷贝 bin\obj\增量编译缓存含旧绝对路径，出现"明明改了却没生效"类怪错不拷；到新机先删干净再编译
3. 旧进程锁定 exe编译报 MSB3021，无法出包编译前关闭软件；脚本已内置此检查并会提示
4. 链接工程漏加依赖MvpE2E / PerfProbe 编译失败（NAudio、UseWPF 各踩过一次）按 5.2 第 2 条同步 csproj
5. FFmpeg 版本漂移新版要求 NVENC API 13.1 / 驱动 ≥610，硬编码直接失败只认 FFmpeg 6.0；用附录 SHA256 校验
6. 目标机没有 NVENC自动改软编码，CPU 占用升高但功能正常属设计内回退，不要误判为故障
7. 目标机没有麦克风界面提示忽略麦克风，成片只有系统声正常降级；有设备的机器再验讲解声
8. 热键被占用F9/F10 失效界面黄字提示；用悬浮条操作
9. 装在只读目录（Program Files）配置和日志写不进去；"删目录即卸载"失效解压到 D:\ 等可写位置
10. 误以为 GC 也要配环境白装 Windows SDK、白配 CsWinRTGraphics Capture 已冻结，产品工程只需 .NET 8 SDK
11. 移动 tools\ffmpeg.exe编码组件缺失，无法开始录制保持 tools\ 与主程序同级，整目录移动
12. 中文路径担心乱码当前项目本身就在中文路径 E:\开发练习项目\录屏软件\，实测正常，无需改名
13. 悬浮条被录进画面成片右侧出现控制条已用系统级捕获排除 + 实底窗口解决；若重现请查日志与窗口样式

7. 一键核对清单

□ 新电脑已装 .NET SDK 8.0.428，dotnet --version 验证通过
