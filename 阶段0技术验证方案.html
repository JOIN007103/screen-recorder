技术选型候选与验证矩阵

针对 C# + .NET 技术栈，列出三类关键选型的候选方案。每类标注推荐项与验证要点，最终以 Spike 实测数据为准。

2.1 屏幕捕获方案

候选方案优势局限 / 验证要点
Windows Graphics Capture 推荐WinRT 官方 API，支持窗口与显示器捕获，光标开关可控，性能较好Win10 1803+；验证捕获边框提示能否隐藏、帧获取延迟
DXGI Desktop Duplication性能高，支持脏矩形检测，CPU 占用低仅支持显示器不支持单窗口；全屏独占场景受限；实现复杂
GDI BitBlt 后备兼容性最好，实现最简单CPU 占用高，1080p/30fps 可能吃力；硬件加速内容可能黑屏

2.2 H.264 编码与 MP4 封装方案

候选方案优势局限 / 验证要点
Media Foundation Sink Writer 推荐Windows 内置，硬件 MFT（NVENC/QSV/AMD）优先，可直接输出 MP4需 COM 互操作；验证硬件 MFT 可用性与软 MFT 回退
FFmpeg / libx264 封装跨平台、控制力强、编码质量稳定需引入原生库与封装层；打包体积与许可证需评估
Windows Media TranscodingAPI 简单，上手快控制力弱，难以满足 30fps 与低延迟要求

2.3 UI 框架方案

候选方案优势局限 / 验证要点
WPF 推荐矢量渲染、样式能力强，适合悬浮控制条与效果渲染D3D 预览需互操作；验证与捕获帧的整合方式
WinForms开发快、门槛低UI 表现力弱，三项鼠标效果与悬浮体验受限
选型策略：推荐组合为 Graphics Capture + Media Foundation + WPF，并以 GDI BitBlt + 软编码 作为回退组合。Spike 的目标不是证明推荐方案"能用"，而是验证它在目标机型上"达到基线"，同时在集显机型上确认回退组合可用。

Spike 任务清单（5 人日）

五个 Spike 按依赖顺序执行，每个给出目标、步骤与通过标准。全部通过后进入出口决策。

S1环境搭建与骨架工程0.5 人日
目标：搭建 C# + .NET x64 工程，确认 Graphics Capture、Media Foundation COM 引用可用。
步骤：① 创建 .NET 桌面工程；② 引入 WinRT 与 Media Foundation 互操作引用；③ 编译运行空窗口。
通过标准：工程编译通过，所需 API 可正常调用，无环境缺失报错。
S2全屏捕获链路验证1.5 人日
目标：验证 Graphics Capture 在独显机型上稳定捕获 1080p/30fps 全屏画面。
步骤：① 创建 GraphicsCaptureSession 捕获主显示器；② 通过帧池获取 D3D 帧；③ 连续捕获 10 分钟并记录帧率与 CPU；④ 重复测试 GDI BitBlt 作对比。
通过标准：帧率稳定 ≥28fps，画面无黑屏/花屏，CPU 占用满足 2.1 基线；边框提示可隐藏或可接受。
S3H.264 编码与 MP4 落盘验证1.5 人日
目标：验证 Media Foundation Sink Writer 将捕获帧编码为 H.264 并写入 MP4。
步骤：① 配置 H.264 编码器 MFT（硬件优先）；② 设置 1080p/30fps 与码率参数；③ 将 S2 捕获帧送入编码器；④ 落盘为 MP4 并检查文件可播放。
通过标准：成功产出可播放的 MP4；编码无丢帧；硬件 MFT 在独显机型可用；集显机型软 MFT 回退成功。
S4端到端串联与基线测量1.0 人日
目标：串起"捕获 → 编码 → 落盘 → 回放"最小链路，采集完整基线数据。
步骤：① 串联 S2/S3；② 连续录制 10 分钟；③ 用监测工具记录 CPU/GPU/内存/帧率；④ 用三类播放器验证 MP4 兼容性。
通过标准：端到端无阻断缺陷；基线数据完整；MP4 在 Windows 播放器、手机、网页均可播放。
S5验证报告与决策输出0.5 人日
目标：汇总数据，固化选型与基线，输出 Go/No-Go 决策。
步骤：① 整理基线与兼容性数据；② 确定捕获/编码/UI 三项选型；③ 核对 WBS 工时估算；④ 输出技术验证报告与决策记录。
通过标准：报告含明确的选型结论、量化基线、风险清单与 Go/No-Go 结论。

量化验收基线

以下指标将"流畅优先"这一定性要求转化为可测量的验收标准。S4 实测后填入实际值，作为阶段 1 的验收依据。

指标目标阈值测量方法实测值（S4 填入）
捕获帧率稳定 ≥ 28 fps（目标 30）帧池连续采样 10 分钟统计待测
CPU 平均占用< 20%Performance Monitor 采样均值待测
CPU 峰值占用< 30%Performance Monitor 采样峰值待测
GPU 占用记录实测值，不作硬阈值任务管理器 GPU 监测待测
内存增长10 分钟 < 50 MB进程内存前后对比待测
编码延迟< 100 ms采集到落盘的时间差抽样待测
MP4 兼容性3 类播放器均可播放Windows/手机/网页各播放一次待测
基线使用规则：阈值是"进入阶段 1 的门槛"，不是"阶段 1 的交付指标"。若 S4 实测低于阈值，须在 S5 触发回退决策（降分辨率/降帧率/切换捕获方案），并同步修正 WBS 工时，不得带病进入开发。
